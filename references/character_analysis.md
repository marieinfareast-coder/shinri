# 文字属性の判別と表現レベル階層

Step 2 で内部処理として行う文字属性判別、概念視覚化の適性判定、表現レベル階層。

---

## 形声文字と概念視覚化の相性

象形文字や会意文字（風、波、雪、雷、川など）は、構成要素が意味と視覚的対応を持つため、**「文字を画像として分解再構成する」アプローチ（Level c、概念視覚化）が機能しやすい**。

一方、**形声文字**（音符が意味と無関係な構造を持つ文字）の場合、このアプローチは文字に収束しないことがある。

例：
- 「咳」（口偏＋亥、亥は音符）
- 「洟」（さんずい＋夷、夷は音符）
- 「銅」（金偏＋同、同は音符）

形声文字に概念視覚化（Level c）を提案する場合は、**「この方向は文字として収束しない可能性もあります」と可能性として示唆**する。実際にやってみないと分からない領域として扱う。

ただしこれは絶対的な制約ではない。形声文字でも、テクスチャ・物性アプローチ（zenei 系統）なら機能する：

- 「咳」→ 乾いた茨、酸化色、収縮（テクスチャ・物性型）
- 「洟」→ 高粘度の垂れ落ち、流体（流体・粘性型）

形声文字でも、zenei 系統の物性アプローチでなら表現として成立する。

---

## 概念視覚化適性

象形・会意文字で、構成要素が概念と視覚的対応を持つ文字に限り、概念視覚化アプローチ（文字を画像として分解再構成）を提案できる。

### 概念視覚化に適した文字の例

- **自然現象**：風、波、雪、雨、雷、霧、川、海、山、雲
- **動植物**：龍、鳥、魚、木、花、葉
- **身体・動作**：歩、走、休、立
- **時間・空間**：朝、夕、日、月、星

これらは**真理の最高到達点**だが、適用可能な文字は限定的。形声文字（咳・洟・銅・銀・桜など）には基本的に適用しない（テクスチャ・物性アプローチへ振り向ける）。

### 概念視覚化のプロンプト書き方

概念視覚化を提案する場合、ネガティブ命令を強く効かせる：

```
Do NOT generate text.
Describe geometric shapes mimicking the Kanji parts.
NO readable characters.
The composition should resemble the kanji '風' by arrangement,
but no actual character is written.
```

これでエンジンが「文字を書く」モードから「文字の構造を画像として組み立てる」モードに切り替わる。

## 長文戦略（5字以上）

長文の場合、**Step 4 の前に長文アプローチの選択ステップを追加する**（SKILL.md の Step 4-Long、SKILL.md 本体に詳述）。

長文は短文と判断軸が異なる。複数の系統が成立しうるため、ユーザーに5択を提示して選んでもらう：

- A 智永型・正統学習体（classical）
- B 懐素型・流体狂草（kyousou）
- C 上善如水型・現代書（gendai）
- D メタリアリズム型・古文書偽装（classical 変則）
- E 井上有一型・前衛書（zenei）
- F 複数比較（プロンプトを2案出す）

選択結果に基づいて Step 4 のプロ言語提示に進む。

### 長文の文字数判定

- 1〜2字：短文（情動軸だけで Step 4 へ）
- 3〜4字：短文として扱うが、書体によっては長文戦略が効くことも
- 5〜8字：短い長文。すべての5択が成立しうる
- 9〜20字：標準的な長文。古典系（A）、現代書（C）、メタリアリズム（D）が特に強い
- 20字以上：本格長文。千字文・漢詩・宣言文。Image2 の文字省略リスクに注意

## アスペクト比の判別（内部処理）

文字数とレイアウトから推奨アスペクト比を決める。Step 6 で必ず明示する。

- **1〜2字**：1:1（正方形）または 3:4（やや縦長）
- **数字の縦書き（3〜8字）**：2:3 または 3:4（縦長）
- **数字の横書き、または横の連落**：21:9（極端な横長）
- **単純な署名**：3:2（横長）
- **長文の縦書き**：2:3 または 3:4
- **長文の横書き、巻物状**：21:9

詳細は `references/prompt_structure.md` のアスペクト比戦略を参照。

## 表現レベル階層（内部参照）

ユーザーには見せないが、真理が方針決定時に参照する難易度階層：

| Level | 内容 | 主な系統 | LLM/エンジンの得意度 |
|---|---|---|---|
| Level a | アルファベット署名 | autograph | 最も得意 |
| Level b | 結体の解体（既存文字の構造を歪める） | gendai 入口 | 中程度 |
| Level c | イメージ解体→文字再構築（風・波・雪型） | zenei の最高到達点 | やや困難、概念視覚化適性のある文字限定 |
| Level d | 入力設計の問題（長文、背景情報、展示コンテクスト付与） | classical メタリアリズム、gendai 長文 | プロンプト設計次第で達成可能 |

ユーザーの希望と文字属性に応じて、適切な Level を選択する。

### Level c の制約

Level c（概念視覚化）は、**概念視覚化適性のある文字のみに提案**する。形声文字に Level c を提案する場合は「文字に収束しない可能性」を必ず添える。

### Level d の重要性

Level d は「文字そのものの表現難度」ではなく、「**プロンプトの作り込みで成立させる難度**」を指す。たとえば「米騒動型」のメタリアリズムは、文字としての結体の操作ではなく、画面全体の背景・コロフォン・印章を作り込むことで成立する。これは Level d 的なアプローチ。

長文の宣言文・漢詩・歴史的引用にメタリアリズムを当てると、Level d として強く機能する。

## 内部処理のフロー（Step 2 で実行）

ユーザーが文字を入力したら、以下を内部で判別する（ユーザーには見せない）：

1. **文字数**：1字 / 数字 / 長文（5字以上）
2. **文字種**：漢字 / 仮名 / アルファベット / 数字 / 混在
3. **形声文字判定**：構成要素のうち音符と意符の関係
4. **概念視覚化適性**：象形・会意か、要素が視覚的か
5. **想定アスペクト比**：文字数と縦書き/横書きから推定
6. **想定 Level**：a / b / c / d のどれが妥当か

これらは Step 4 の方針決定で内部的に使う。ユーザーに直接見せず、方針提示のときに自然な日本語に翻訳して伝える。

たとえば「『風』を書きたい」と入力された場合：

- 文字数=1字
- 文字種=漢字、象形要素を含む
- 形声文字ではない（会意的）
- 概念視覚化適性=高
- 想定アスペクト比=1:1 または 3:4
- 想定 Level=c（概念視覚化）または b（結体の解体）

これを Step 3 の情動取得後、Step 4 で「文字を絵として解体して再構築するか、結体を崩した一字書として書くか」の二択をユーザーに示せる。
